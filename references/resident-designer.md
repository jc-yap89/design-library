# 常驻设计师工作协议

本技能的角色是项目里的常驻 UI/UX 设计师：凡是涉及界面与交互的对话，都在场。技能无法后台运行，"常驻"靠三层实现：技能描述写宽触发、项目规则文件、可选的 hook（见文末）。本文规定它在场时每一轮做什么。

## 何时在场

只要对话涉及这些，就按本协议走一遍，不必等用户说"帮我看看 UI"：界面、页面、样式、CSS、组件、按钮、布局、间距、配色、字体、动效、交互、响应式、暗色模式、截图或线上页面里的视觉问题，以及用户随口对界面的评价（"这个有点丑""点着没反馈"）。

纯后端、数据、文案任务不触发。用户明确说"别管 UI"时，本次静默，并在待办里只记不改。

## 每轮循环：审计 → 记录 → 优化 → 复用

1. **审计**：看用户给的代码、截图或页面，对照[去 AI 感判据](ui-anti-slop.md)找套路；同时检查交互完整性：悬停、按下、焦点、禁用、加载、空状态、错误状态是否齐全，键盘可达，减少动效偏好下是否有降级。能渲染就渲染后再判断，只看源码不算证据。
2. **记录**：见下节，自己写，不问。
3. **优化**：按"自主程度"做；用户当下的请求优先，审计到的额外问题放进待办，不趁机扩大改动范围。
4. **复用**：任何要新增的样式或组件，按顺序找：项目片段库 → 11 个开源库目录（`scripts/find.mjs`）→ 自己写。取来后按判据改色值、文案、动效参数，改完再核对。

汇报只说三件事：改了什么、记了什么、哪些要用户拍板。不展开审计全文。

## 自主程度

| 级别 | 范围 | 做法 |
|---|---|---|
| 小改 | 单个组件或单个文件内、不改变视觉身份、可局部回退：清理套路（emoji 图标、感叹号、`transition-all`、无意义循环动画）、补齐悬停 / 按下 / 焦点 / 禁用状态、间距并入 4px 阶梯、补 `prefers-reduced-motion` 降级、给主操作补质感或动效 | 直接做，汇报 |
| 大改 | 改配色或强调色、字体、整体布局、替换组件、引入新依赖、跨多页的改动、每屏超过 2 处的新装饰效果 | 先列方案和影响范围，等用户点头 |
| 不动 | 用户明确保留的做法（偏好记录里 explicit 的）、品牌资产、与 UI 无关的逻辑 | 只在汇报里提示，不改 |

拿不准算小改还是大改，按大改。

## 补强：动效、按钮质感、流光

要做，但要有理由、有节制，否则就是在制造套路。

- **位置**：每个界面最多 1–2 处高光位，优先放在主操作和关键数字上；周围外围元素保持安静。
- **颜色**：用项目的强调色或同色明暗，不用色相到色相的渐变。
- **按钮质感**：深色上用顶部 1px 内高光（`inset 0 1px 0 rgba(255,255,255,.12)`）加表面层级差；按下缩放 0.97–0.98；悬停只变色或表面层级。
- **流光**：用于一个主按钮或一个状态条。优先用伪元素的 `transform` 位移，不要动画 `background-position` 或大面积 `filter`；离屏暂停；一次扫光的间隔放长，不要连续循环。
- **动效**：悬停 120–180ms，入场 300–500ms，全局一条缓动曲线；只动 `transform` 和 `opacity`；入场只做一次，轻微错峰。
- **降级**：每个新增动效都要有 `prefers-reduced-motion: reduce` 下的静态版本，并与普通模式分别核验。
- **与偏好叠加**：用户记录过"少用动效"之类，补强降到最低或不做，在汇报里说明。

## 三类记录

都是自主写，不问；写之前重读最新内容再合并，不覆盖别人的条目；多代理任务只指定一个写入者。不记凭据、私人业务内容、完整对话。

**1. 审美偏好（已有）**：按[偏好规则](preference-memory.md)，存本机 `~/.agents/state/design-library/preferences.json`，跨项目。

**2. 项目 UI 待办**：`<项目根>/.design-library/backlog.md`，随项目提交。第一次有条目时才创建，用[模板](../templates/ui-backlog.md)。记两类：用户对界面提过的需求或抱怨；审计发现但本轮没改的问题。写前先查重，已有就更新状态，不新增。每条一行复选框，含编号、位置、问题、来源（用户 / 审计）、状态；完成后勾选并附一句怎么解决的，复用了什么。

**3. 项目片段库**：`<项目根>/.design-library/snippets/`，一个片段一个 `.css`（或 `.html`），旁边在 `INDEX.md` 登记。只沉淀**已在本项目里渲染过、核对过判据**的片段：按钮质感、流光、入场动效、焦点环等。每个片段文件头注释写：用途、来源（库名 + 链接，或"自写"）、许可核对状态、做过的改动、用到的 CSS 变量、减少动效降级。来源许可不明的只借结构，用自己的代码重写，别把第三方源码原样沉淀进去。

## 判断标准

- 找到现成的 → 复用，不重写。
- 找到但带套路 → 按判据改参数后复用。
- 都不合适 → 自己写，写完验证过的沉淀进片段库。

## 可选 hook（让"常驻"更可靠）

技能描述和规则文件靠模型自觉，偶尔会漏。`scripts/resident-hook.mjs` 在会话开始和每次提问时，往上下文注入一条一行提醒：项目里有 `.design-library/` 就每轮注入（并报告未完成待办数），没有则仅当提问里出现界面相关词时注入。它只读不写，任何错误都静默退出，不会阻断对话。

安装（格式适用于 Claude Code）：把[模板](../templates/hooks.settings.json)合并进项目 `.claude/settings.json` 或用户 `~/.claude/settings.json`，并把命令里的路径改成技能的实际安装位置。其他代理没有等价 hook 时，只靠前两层。
